# PaperEdit PDF 转 Word 功能设计

日期：2026-10-14

## 已确认的目标

用户已确认在现有 PaperEdit 中增加 PDF 转 Word 功能。第一版处理能够提取文字的 PDF，生成可在 Microsoft Word 和 WPS 中继续编辑的 `.docx`。文件在本地处理，兼容现有 macOS Apple Silicon 应用与 Windows x64 免安装包。

导出应包含当前已经应用的编辑，以及点击导出时正在输入、能够正常应用的文字修改。优先保留文字内容和阅读顺序，同时尽量保留字体样式、图片、表格和分页。不能承诺与 UPDF 的结果或原 PDF 完全一致。

## 范围与限制

- 支持整份文档导出，包含中文、英文、普通段落、图片和可识别的表格。
- 输出中的 PDF 文字应转换为 Word 文字，不能通过整页截图冒充可编辑转换。
- 复杂多栏、特殊字体、浮动元素和不规则表格的还原效果依赖转换引擎与文档结构；说明中明确可能需要在 Word 中调整。
- 本版不包含 OCR、批量转换、指定页码转换、Word 转 PDF 或其他格式。
- 整份文档无可提取文字时拒绝转换，提示扫描件需要 OCR。混合文档允许转换，提前提示无文字且包含图片的页可能保留为图片，图片内文字不可编辑。完全空白页不提示为扫描件。
- 第三方库安装、实际文档测试和冻结应用验证均属于后续实现工作；当前仅完成接口和验收设计。

## 技术方案

采用 `pdf2docx` 作为转换引擎，由 `python-docx` 生成 DOCX。此前查询到 PyPI 版本为 `0.5.13`，要求 Python 3.10 以上及 PyMuPDF 1.26.7 以上，与项目 Python 3.12、PyMuPDF 1.27.2.2 的声明要求相容；实际兼容性需测试验证。新增依赖使用固定版本，并在两种平台验证。

自研 PyMuPDF 文字提取加 DOCX 拼装需要重新实现排版和表格识别；调用系统办公软件则不能满足独立运行要求，因此不采用这两个方案。

转换层独立于 Qt，输入为当前文档快照、目标路径和导出权限信息，输出为成功结果或面向用户的转换错误。`DocumentSession` 负责保留打开文档时的权限，并提供快照；转换不会改变撤销历史或 PDF 的已保存标记。

导出任务通过 Qt 的异步任务控制运行。转换使用独立的本地工作进程，避免转换期间与现有页面渲染同时在一个进程调用 PyMuPDF。开发模式和冻结应用都提供内部转换入口，使用当前 Python 或应用本身启动，不依赖用户安装 Python、Word、WPS、LibreOffice 或其他外部程序。

## 用户流程

1. 工具栏与“文件”菜单增加“导出 Word”。没有打开 PDF 时禁用。
2. 点击后先应用待提交的文字编辑。如果编辑无效，保留输入并提示原因，不开始转换。
3. 检查文字提取权限与是否存在可提取文字。禁止提取的文档提示权限限制；扫描件提示本版不支持 OCR。
4. 对包含扫描图片页的混合文档说明图片文字不能编辑。对受密码保护的 PDF 说明生成的 Word 不带原 PDF 密码保护，用户可继续或取消。
5. 打开保存对话框，默认名称为原文件同名 `.docx`，缺少后缀时补齐。已有目标文件沿用系统保存对话框的覆盖确认。
6. 从当前文档生成不可变快照，启动转换；显示“正在转换为 Word”的状态或忙碌进度，不显示未经测量的百分比。单个窗口同时只允许一个转换任务。
7. 工作进程处理快照；原 PDF、编辑会话和已有输出文件在成功前均保持不变。转换期间界面可刷新，并防止启动重复任务。
8. 成功后提示文件路径，并提供打开所在文件夹的入口。Word 导出不等同于保存 PDF，仍未另存的 PDF 修改保持未保存状态。
9. 失败时显示可理解的原因并清理临时文件。用户可以修正路径或文档后再次导出。

关闭应用时如有正在执行的转换，提示用户继续等待或取消转换后关闭。取消应终止工作进程、清理临时文件，且不能覆盖已有目标文件。关闭流程继续沿用现有 PDF 未保存提示。

## 数据与输出安全

- 正确输入密码后才能读取加密 PDF；保留原始的文字提取权限，不能因为工作快照解密而忽略限制。所有者认证可导出；普通打开密码需要文档允许提取文字。
- 目标只允许 `.docx`，不能覆盖原 PDF；异常路径、只读目录、磁盘写入错误转换为用户提示。
- DOCX 在目标目录中的临时路径生成，转换完成后检查 ZIP 完整性、必需的 Word 文档部件及可解析性，再原子替换目标文件。
- 禁用转换引擎默认的忽略页面错误行为：某页解析或生成失败时不能提示整份文档成功。
- 工作快照如需暂存，只写入权限受限的本地临时目录，不上传；任务成功、失败、取消时均释放。程序下次启动可清理本应用遗留的临时任务目录。
- 工作进程关闭转换器并返回结构化结果；不将 PDF 正文、密码或私人文档写入日志或公共测试样本。

## 验收

测试使用人工生成的非私人 PDF，预期内容独立于转换实现。

1. 转换含中文、英文和两页内容的 PDF，Word 中可以提取并编辑相应文字，顺序与分页结构合理。
2. 转换包含图片和普通网格表格的 PDF，DOCX 包含图片，表格内容以可编辑 Word 表格保留；检查内容、单元格与边界。
3. 导出包含当前修改的快照，原 PDF 的字节不变；导出后撤销、重做与 PDF 未保存状态正常。
4. 扫描件、混合文档、空白页、损坏文件及加密文档分别走正确的提示或权限分支。
5. 目录不可写、转换器报错、页面失败、输出校验失败及取消转换，均不破坏已有目标文件，并清理临时产物。
6. 界面验证待提交编辑、重复导出、进度结束与关闭期间的任务行为。
7. 原有测试全部通过；Mac 实际构建并测试转换，Windows CI 构建免安装包并在解压后的程序中执行转换验证，不能只检查启动成功。
8. 用可用的办公文档渲染工具或 Word/WPS 对生成样例进行视觉检查，记录排版差异；没有实际渲染工具时说明验证限制，不宣称排版完全还原。
9. 新构建保留旧发布包供用户回退；软件包发布是实现和验证完成后的步骤。
